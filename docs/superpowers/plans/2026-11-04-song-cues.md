# Song Cues Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Songs area in DLLC where a song gets free-named sections with notes/lyrics, and any section(s) or range exports as an iPhone-ready MP3/WAV or lyric video with optional padding, fade, count-in and speed.

**Architecture:** Pure logic (models, storage, naming, range math, count-in synthesis, ffmpeg argument building, waveform peaks) lives in `DLLCCore` with Swift Testing tests, including real-ffmpeg checks. The UI lives in `Sources/DLLC/Song*.swift`, reached from a "Songs" sidebar section; playback uses AVPlayer with pitch-preserving rate; exports run the bundled ffmpeg through `ProcessSupervisor`.

**Tech Stack:** Swift 6, SwiftUI/AppKit, AVFoundation (AVAssetReader, AVPlayer), bundled ffmpeg (atrim, atempo, afade, concat, drawtext with harfbuzz, libmp3lame), Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-04-song-cues-design.md`

## Global Constraints

- macOS 15+, Apple Silicon; no new dependencies; no network.
- Subprocess arguments are arrays; never through a shell.
- The song file is never modified; exports never overwrite (`Hook 2 (2).mp3`); user files never deleted.
- MP3 256 kbps default; WAV optional; lyric video 1280×720, 30 fps, H.264 + AAC.
- Speeds: ×4, ×3, ×2, ×1, ×0.5 (slow 2×), ×0.33 (slow 3×), ×0.25 (slow 4×). Pitch kept; the count-in is not sped up.
- Count-in: 3/4/5/8 counts; interval 1 s or 0.5 s; sound beep/click/woodblock; first tick accented.
- Padding before/after: 0, 1, 2, 3, 5, 10 s, or typed; fade out on/off, 1.5 s.
- Waveform peaks are cached under Caches (counts toward the cache policy, rebuildable).
- Lyric text font: `/System/Library/Fonts/Supplemental/Arial Unicode.ttf` (covers Thai and Hangul); text goes through `textfile=` (never inline-escaped).

## Review Focus

- A section whose padding runs past the start or end of the song: clamp to the song; never fail. (Task 1 test `paddedRangeClampsToSong`.)
- A song file that moved or was deleted after its sections were made: the song shows "File missing — Locate…", sections are kept. (Task 5 test `missingFileKeepsSections`.)
- Section names with `/` or `:` (e.g. "Verse 1/2"): the file name must be safe. (Task 1 test `unsafeNamesAreCleaned`.)
- Lyrics with Thai/Korean text and quotes/colons: rendered verbatim. (Task 4 test `lyricTextGoesThroughFiles`.)
- MP3 export of an exact section must start on the section (no encoder-delay offset beyond 30 ms) and last the expected time. (Task 2 test `exportDurationsMatch`.)

### Task 1: Song model, storage, naming, range math

**Files:**
- Create: `Sources/DLLCCore/Song.swift`, `Tests/DLLCCoreTests/SongTests.swift`

**Interfaces — Produces:**
- `struct SongSection: Codable, Hashable, Identifiable { id: UUID; name: String; start: Double; end: Double; note: String; lyricTimes: [Double?] }` (lyric lines are `note` split by newline; `lyricTimes[i]` is a tap-timed start, song time).
- `struct Song: Codable, Identifiable { id; title: String; path: String; bookmark: Data?; projectID: UUID?; duration: Double; sections: [SongSection]; prefix: String; addedAt: Date }` with `mutating func insert(_:)` that keeps sections sorted and non-overlapping (a new section is clipped to the gap it starts in).
- `enum CueSpeed: Double, CaseIterable { x4 = 4, x3 = 3, x2 = 2, x1 = 1, half = 0.5, third = 0.3333333333, quarter = 0.25 }` with `label` ("×2", "×0.5 (slow 2×)", "×0.33 (slow 3×)"…), `fileSuffix` ("x2", "x0.5", "x0.33", "" for ×1).
- `enum CountInSound: String, Codable, CaseIterable { beep, click, woodblock }`; `struct CountIn: Codable, Hashable { count: Int; interval: Double; sound: CountInSound }`.
- `enum CueFormat: String, Codable, CaseIterable { mp3, wav, lyricVideo }` with `fileExtension`.
- `struct CueOptions: Codable, Hashable { padBefore = 0.0; padAfter = 0.0; fadeOut = false; countIn: CountIn? = nil; speed = CueSpeed.x1; format = CueFormat.mp3 }`.
- `enum CueMath { static func range(of sections: [SongSection]) -> TimeRange?` (first start → last end; nil if empty) `; static func padded(_ r: TimeRange, options: CueOptions, duration: Double) -> TimeRange` (clamped) `; static func outputDuration(range: TimeRange, options: CueOptions) -> Double` (= range/speed + count·interval) }`.
- `enum CueNaming { static func baseName(sections: [SongSection], range: TimeRange, songTitle: String, prefix: String, speed: CueSpeed) -> String; static func uniqueURL(in folder: URL, base: String, ext: String) -> URL }` — 1 section: name; 2–3: joined `+`; >3: `first→last`; none: `"<title> 1m42s-2m31s"`; prefix + space before; speed suffix after a space; `/ : \` and control chars become `-`.
- `final class SongStore { init(url: URL); func load() -> [Song]; func save(_ songs: [Song]) }` (atomic JSON).

### Task 2: Count-in synthesis and audio export command

**Files:**
- Create: `Sources/DLLCCore/CueAudio.swift`, `Tests/DLLCCoreTests/CueAudioTests.swift`

**Interfaces — Consumes:** Task 1 types. **Produces:**
- `enum CountInSynth { static func wav(_ c: CountIn, sampleRate: Int = 48_000) -> Data }` — 16-bit stereo PCM WAV, length `count × interval`; each tick ≈ 60 ms with exponential decay at the start of its slot; first tick accented (beep 1760 Hz vs 880 Hz; click = short noise burst high-passed/accented louder; woodblock = 1200/900 Hz with fast decay).
- `enum CueCommand { static func audio(song: URL, range: TimeRange, options: CueOptions, countIn: URL?, output: URL) -> [String] }` — filter graph: `[0:a]atrim=start:end,asetpts=PTS-STARTPTS,<atempo chain>,<afade=t=out:st=(len−1.5):d=1.5 if fadeOut>[m]`; with count-in `[1:a]aformat=sample_rates=48000:channel_layouts=stereo[c];[c][m]concat=n=2:v=0:a=1[out]`; MP3 `-c:a libmp3lame -b:a 256k`, WAV `-c:a pcm_s16le`; `-ar 48000 -ac 2`; `-map_metadata -1`.
- `static func atempoChain(_ speed: Double) -> [String]` — split into factors within [0.5, 2] (×4 → 2,2; ×3 → 2,1.5; ×0.33 → 0.5,0.666…; ×0.25 → 0.5,0.5).
- `final class CueExporter { init(ffmpeg: URL, supervisor: ProcessSupervisor = .shared); func export(song: Song, sections: [SongSection], range: TimeRange, options: CueOptions, to folder: URL) async throws -> URL }` — writes count-in WAV to a temp dir (removed after), chooses `CueNaming.uniqueURL`, runs ffmpeg, renders to `name.partial.ext` then moves into place.

- [ ] **Step 1: Tests** `atempoChainStaysInRange` (each factor in 0.5…2, product = speed ±0.001), `countInLengthAndAccent` (data size matches `count×interval`; first tick peak > second), `exportDurationsMatch` (real ffmpeg, guarded by tools presence like FFmpegTests: generate a 20 s sine with ffmpeg, export 5–9 s with 3×1 s count-in ×1 → ffprobe duration 7.0 ± 0.06; same at ×2 → 5.0 ± 0.06; WAV exact ±0.01), `fadeOutAddsNoLength`, `exportNeverOverwrites`.
- [ ] **Step 2:** run → fail. **Step 3:** implement. **Step 4:** `swift test --filter CueAudio` → PASS. **Step 5:** commit `feat(songs): count-in and audio export`.

### Task 3: Waveform peaks

**Interfaces — Produces:**
- `struct WaveformPeaks: Codable { let peaksPerSecond: Int; let values: [Float] }` (max |sample| per bucket, 0…1) with `func slice(from: Double, to: Double, buckets: Int) -> [Float]` (max-pooled for drawing).
